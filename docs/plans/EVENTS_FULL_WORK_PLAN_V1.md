## 1. Что такое «события»

**Событие** — анонс мероприятия в районе: встреча, концерт, ярмарка, мастер-класс, эфир, праздник.

На карточке обычно: название, дата/время, место или «онлайн», описание, цена, контакты или ссылка на регистрацию.

Это **не** бизнес (салон/магазин) и **не** вакансия. Это то, что происходит в конкретный день — «куда сходить».

## 2. Кто создаёт события сейчас

| Кто | Как |
|---|---|
| Пользователь сайта | Страница «Добавить событие» (`/events/new`), нужен вход |
| Админ / модератор | Очередь проверки (Inbox → вид «Events»), одобрение карточки |
| Из чатов | Пост из Telegram / Facebook попадает в очередь → человек одобряет → событие на сайте |
| Скрипт (вручную) | Публикация из рекомендаций (Facebook/Telegram), запускается руками |

## 3. Что уже есть

### На сайте (для людей)

- Список событий и календарь (`/events`) — **по умолчанию предстоящие**
- Страница одного события (`/events/[slug]`)
- Форма «Добавить событие» + дата или «Дата уточняется»
- **Мои события** (`/events/mine`) и правка своих (`/events/[slug]/edit`)
- Фильтры по времени / региону
- Карточка события с оформлением

### В админке

- Inbox → Events
- Каталог: **смотреть, править, архивировать** (`/admin/catalog/events`, `…/[id]/edit`)
- Кнопка «В архив все прошедшие»
- Одобрение из импорта с проверкой даты
- Заявки claim (как раньше)

### В данных и правилах

- Статусы draft / published / archived
- Публикация пользователя сразу на сайт (**путь A**)
- Владелец = создатель; админ может править любое
- Миграция: владелец читает свои события (`20260926220000_events_owner_select.sql`) — **нужно применить в Supabase**

## 7. Критерии «полностью работают»

1. Человек находит ближайшие — **да (default upcoming)**  
2. Создать понятно — **да**  
3. Админ правит и убирает — **да в коде**  
4. Прошедшие не засоряют ленту — **да**  
5. Импорт без пустой даты молча — **да**  
6. Контакты в полях — **да при create/approve**  
7. Понятные двери — **да**  

Осталось: миграция в базе + ручная проверка Inbox + согласие команды + merge.
