# Как партнёрам работать с Team Agent

Сэм, Никитос и Жека в разговоре равны. Подтверждение опасного действия зависит от сохранённых прав, а не от формулировки «главный».

1. Взять актуальную main.
2. Создать свою feature branch. Не работать втроём в одной ветке.
3. В Telegram написать, кто что берёт, и попросить `@kroogy_bot распредели работу`. Запись будет предложением.
4. Известный участник подтверждает: `/agent approve <id>`.
5. На компьютере, после заметных правок: `npx tsx scripts/team-agent-local-report.ts`.
6. Commit фиксирует SHA. Push делает ветку видимой на GitHub. Это ещё не сайт.
7. Pull request создаётся отдельно, когда работа готова к просмотру.
8. Preview READY с тем же SHA, что и ветка, означает «можно смотреть». Production READY с тем же SHA означает «это на сайте».
9. Merge в main не публикует сайт сам по себе. После публикации спросить: `@kroogy_bot что сейчас выложено на сайт?`
10. Не делать force push. Не менять production env, домен и webhook. Не применять миграции из чата.

Если reporter давно не запускался, бот скажет, что локальный статус устарел.
