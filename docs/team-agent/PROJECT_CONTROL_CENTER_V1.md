# Project Control Center V1

Team Agent остаётся тем же Telegram-помощником. Этот слой добавляет к нему общую картину проекта.

Источники независимы:

- GitHub — удалённый git, ветки, PR, проверки. Только чтение.
- Vercel — Preview и Production. Только чтение deployment.
- Supabase — имена локальных миграций и, если задан отдельный management token, удалённая история.
- Cursor reporter — ветка, SHA и список путей с компьютера разработчика.
- OpenRouter — проверка ключа, без генерации ответа.
- Telegram — адрес webhook и последняя ошибка доставки.

Сведение делает `reconcileProject`. Оно не вызывает модель.

У задачи два разных состояния. `status` — договорённость команды: предложено, подтверждено, в работе, закрыто. `delivery` — где лежит код: только локально, в GitHub, в PR, на Preview, в main, на сайте. Опубликованный сайт определяется только по SHA production deployment.

Ответ бота берёт короткий текст из снимка. Полный JSON всех сервисов в модель не уходит.

Webhook GitHub и команда сверки обновляют журнал. Постоянное хранение journal, локальных отчётов и предупреждений описано в migration `20260925181702_team_agent_control_center_v1.sql`. Пока она не применена, ответы на статус собираются чтением API, а запись отчёта в базу вернёт `persisted: false`.
